# Task Triage（Claude / Codex 振り分け）

## 目的

依頼されたタスクを「Claudeでやる / Codexでやる / クロスレビューする / 人間に確認する」の
いずれかに振り分け、振り分け先にそのまま渡せる依頼文を生成する。

設計思想：**判断の本体は分岐表（`references/rubric.md`）であり、このスキルはそれを適用するだけ。**
LLMの感覚で毎回判断するとブレる＋自分（Claude）に有利に振りがちなので、
判定理由は必ず分岐表のルール番号で示す。分岐表が実態と合わないと感じたら、
判定自体はルール通りに出した上で、改善提案を別枠で書く（勝手にルールを曲げない）。

## 手順

### Step 1: タスク情報の抽出

タスク文から以下を抽出する。書かれていない項目は文脈から補完してよいが、
補完した項目は必ず「推定」と明示する（勝手に断定すると誤配の原因になる）。

- **目的**: なぜやるのか
- **成果物**: 何ができたら完了か
- **完了条件**: 品質基準・受け入れ条件
- **期限・緊急度**
- **影響範囲**: 本番/検証、可逆/不可逆、社外公開の有無、金額の有無
- **必要なアクセス**: コネクタ（Slack/Notion/Intercom/Gmail等）、対象リポジトリ、Chrome操作 など

### Step 2: ルーブリック適用

`references/rubric.md` を読み、**R1から順に評価して最初にマッチしたルールで判定する**。
判定は次の4種類：`Claude` / `Codex` / `クロスレビュー` / `人間確認`。

注意：「Claudeの方がうまくできそう」という感覚を判定理由にしない。
分岐表にない理由で判定しない。迷ったら確度を下げて人間確認に倒す。

### Step 3: 依頼文の整形

`references/handoff-templates.md` のテンプレを使い、振り分け先にそのまま貼れる依頼文を生成する。
依頼元の文面は文脈が省略されがちなので、**背景・成果物・完了条件の補完がこのスキルの一番の価値**。
特にCodexはこの会話の文脈を一切持たないため、依頼文単体で完結させること。

### Step 4: ログ記録

`references/triage-log.md` に1行追記する。目的は判定の答え合わせ：
後日「実際どうだったか」を記入し、外れが続くルールは `rubric.md` を修正する
（更新ルールは rubric.md 末尾参照）。ファイルに書き込めない環境（Claude.ai等）では、
追記すべき行を出力の末尾に提示してユーザーにコピーしてもらう。

## 出力フォーマット

必ずこのテンプレートで出力する：

```markdown
## トリアージ結果

- **判定**: Claude / Codex / クロスレビュー（実装: ◯◯、レビュー: ◯◯） / 人間確認
- **適用ルール**: R◯（ルール名）
- **確度**: 高 / 中 / 低
- **理由**: （分岐表の条件にどう該当したか、1〜2文）
- **推定で補完した項目**: （あれば列挙。「なし」も明記）

## 依頼文（そのまま貼れます）

（handoff-templates.md に沿った整形済み依頼文。クロスレビューの場合は実装用とレビュー用の2通）

## ルーブリック改善提案

（分岐表が実態と合わないと感じた場合のみ。なければこのセクション自体を省略）

## ログ追記行

| 2026-08-15 | （タスク要約） | R◯ | （判定） | （未記入） | （未記入) |
```

## 判定に迷ったとき

- 複数ルールに同程度マッチする、または情報不足で確度が「低」になる場合は、
  無理に断定せず判定を「人間確認」とし、有力2案をそれぞれ理由付きで併記する。
- 誤配のコスト（やり直し）は確認のコストより高い。迷ったら聞く。
